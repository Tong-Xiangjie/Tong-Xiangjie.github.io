## 项目介绍

**星尘迁徙** 是一个「每次 3～5 分钟、每天上线 1～2 次」的单机养成小游戏。

- **一只星兽**：有饱食、心情、精力、亲密四条状态，和体质、敏捷、智慧、感知四项成长属性。
- **三阶段进化**：幼体 → 成体 → 守护体；成体时根据你的照顾方式与探索选择，走向 **旅者 / 学者 / 园丁** 三个分支。
- **两个探索区域**：微光浅滩、碎星遗迹（后者需要「星图残页」或观星台 2 级）。
- **四种任务**：采集、探险、学习、休息。下线前安排一件，星兽会一直做下去。
- **十种随机事件**：全部是二选一，影响状态、属性或稀有物品。
- **二十种物品、五种建筑、五个成就、四种图鉴分类**（物品 / 见闻 / 访客 / 配方）。
- **离线时间胶囊**：**没有后台进程**。你关掉网页后游戏逻辑完全停止，只留下时间戳；再次打开时用 `now - lastSettleTime` 一次性结算探索报告。
- **迁徙胶囊**：导出存档 = 把星兽封进胶囊；导入存档 = 在新的星门唤醒它。

世界观一句话：**星兽不会在后台替你打工，它只是在你不在的时候，认真地过日子。**

## 怎么开始玩（两种方式）

### 方式 A：**双击就能玩**（推荐先试这个）

直接双击仓库根目录下的：

```text
stardust-migration-single.html
```

这是**单文件版**：CSS 与全部 JS 都内联在一个 HTML 里，没有任何外部请求，`file://` 也能跑，不需要服务器、不需要联网。

> ⚠️ 需要注意：某些浏览器在 `file://` 下会禁用 `localStorage`（Firefox / Safari 较严格），
> 这种情况下进度只存在内存里，**刷新会丢**。游戏检测到这种环境会在设置页和启动时给出警告。
> 想稳定存档，请用方式 B，或者随手用「封入胶囊」导出。

单文件版是从模块源码**自动生成**的，不要直接编辑它。改了 `js/` 下的源码后重新生成：

```bash
cd stardust-migration
node tools/build-single.mjs     # 输出 ../stardust-migration-single.html
```

### 方式 B：本地 HTTP 服务（模块版，存档最稳）

源码是 ES Modules 结构，浏览器不允许通过 `file://` 加载 ES Module（不透明来源会被 CORS 拦截），
所以要**通过 HTTP 打开**。任选一种：

```bash
cd stardust-migration
python -m http.server 8000      # 有 Python 的话
npx serve .                     # 有 Node 的话
npx http-server . -p 8000
# 然后打开 http://localhost:8000/
```

VS Code 用户也可以装 Live Server 插件，右键 `index.html` → Open with Live Server。

### 方式 C：部署上线后直接玩

推到 GitHub Pages 后访问 `https://tong-xiangjie.github.io/stardust-migration/`，见下一节。

把 `stardust-migration/` 里的**全部内容**放到仓库根目录即可，`index.html` 就在根目录，URL 形如：


## 玩法与核心循环

### 第一次打开：三次点击就能玩起来

1. **给它起个名字** —— 打开后会弹出「它醒过来了」，输入名字（或点下面的候选名字）→「就是这个名字」。
2. **去「探索」页安排一件事** —— 先点一个区域（「🌊 微光浅滩」默认已解锁），再点任务：
   - 🧺 **采集**（2 行动点，2 小时）：稳，带回材料
   - 🧭 **探险**（3 行动点，3 小时）：稀有掉落和随机事件更多
   - 📖 **学习**（2 行动点，2 小时）：涨智慧、解锁图鉴
   - 💤 **休息**（1 行动点，4 小时）：回精力，几乎不产出
3. **关掉网页** —— 就这一步。星兽会按你安排的任务自己待着。

下次再打开，会先弹出**离线探索报告**（「你离开的第 2 小时，星兽发现了一片发光苔藓……」），点「领取并继续」资源就入库了。

### 每次上线的固定流程（3～5 分钟）

```text
① 上线 → 查看离线探索报告（时间胶囊结算）
② 领取资源 → 处理随机事件（二选一）
③ 喂食 / 清洁 / 抚摸 → 恢复饱食、心情、精力、亲密
④ 花行动点 → 升级小屋、制作物品、研究图鉴、布置岛屿
⑤ 安排下一次探索：采集 / 探险 / 学习 / 休息
⑥ 下线 → 自动本地存档
⑦ 换设备 → 导出 / 导入「迁徙胶囊」继续
```

### 界面上五个面板分别干什么

| 面板 | 能做的事 |
| --- | --- |
| 🏝️ **主界面** | 看星兽 / 状态条 / 成长属性；**喂食、清洁、抚摸**；看当前安排与星兽记忆；点星兽会有一句随机的反应 |
| 🧭 **探索** | 选区域（碎星遗迹要解锁）→ 安排任务 → 看倒计时进度，也可以「召回星兽」 |
| 🎒 **背包** | 看物品、筛选（材料 / 食物 / 礼物 / 关键物）；点物品可以「使用」；下面是用 **星尘工作台** 制作物品 |
| 📖 **图鉴** | 物品 / 见闻 / 访客 / 配方 四类收集进度，以及 5 个成就 |
| ⚙️ **设置** | **封入胶囊（导出）**、**在新星门唤醒（导入）**、升级建筑、给星兽改名、看统计、重新开始 |

> 💡 主界面顶部的 `⚡行动点` 是核心资源：**每天 0 点后恢复 8 点（上限 12）**。
> 行动点用完就没事干了——这是设计，不是 bug，明早再来。

### 状态与消耗

| 项目 | 说明 |
| --- | --- |
| 饱食 | 随时间下降，用食物恢复；低于安全线会停止下降 |
| 心情 | 清洁、抚摸、事件提升 |
| 精力 | 任务与探险的主要门槛，靠「休息」任务恢复 |
| 亲密 | 决定能否进化，靠抚摸 / 喂食 / 事件积累 |

### 行动点（每天能做多少事）

行动点是**唯一的"日额度"**，也是全局最稀缺的资源：

```
基础上限 12 点 ｜ 每个自然日（本地 0 点后）恢复 8 点 ｜ 未用完的会保留
```

| 行为 | 消耗 |
| --- | --- |
| 喂食 / 清洁 / 抚摸 | 各 1 点 |
| 采集 | 2 点 |
| 探险 | 3 点 |
| 学习 | 2 点 |
| 休息 | 1 点 |

**恢复规则（实测行为）**：

| 情况 | 结果 |
| --- | --- |
| 剩 2 点，隔一天再上线 | 恢复到 **10 点**（+8） |
| 满点 12 离线一天 | 还是 **12 点**（到顶了，超出的部分浪费） |
| 剩 0 点，离线 30 天 | 还是 **12 点**（**不会累积**，别指望攒几天一次花） |
| 一天内反复上下线 | **不会**重复恢复（同一自然日只结算一次） |

连续多天没上线会按天数补，但**始终被上限截断** —— 这是为了配合"每天 3～5 分钟"的节奏，
而不是让你攒一周再一次性刷完。

**提高上限**：升级「🛖 孵化舱」

| 孵化舱等级 | 行动点上限 | 休息恢复加成 |
| --- | --- | --- |
| Lv.1（初始） | 12 | +15% |
| Lv.2 | 13 | +35% |
| Lv.3 | 14 | +50% |
| Lv.4 | 15 | +65% |
| … | 每级 +1（无上限） | 每级 +15% |

> 💡 1 级是初始等级，所以**从 2 级才开始加行动点上限**（升第 1 次花 20 星尘，很划算）。

| 阶段 | 条件 | 备注 |
| --- | --- | --- |
| 幼体 | 初始 | 🥚 Lv.1-4 → 🐣 Lv.5 起 |
| 成体 | Lv.10 + 亲密 ≥ 45 | 此时按倾向选定分支 |
| 守护体 | Lv.22 + 亲密 ≥ 70 + 星辰晶核 ×1 | |
| 守护体·四 | Lv.35 + 亲密 ≥ 85 + 星辰晶核 ×1 | |
| 守护体·五 | Lv.48 + 亲密 ≥ 100 + 星辰晶核 ×2 | |
| 守护体·六 | Lv.61 + 亲密 ≥ 115 + 星辰晶核 ×3 | |
| … | 每级 +13 级 / +15 亲密 | **没有终点**（第 8 形态起改用「星种」） |

### 星兽形象会跟着状态变

形象不是一张固定的图，而是「阶段形象 + 状态表情」两层叠加：
| 阶段 | 形象 |
| --- | --- |
| 幼体 | 🥚（Lv.1-4）→ 🐣（Lv.5-9） |
| 成体·旅者 / 学者 / 园丁 | 🦅 / 🦉 / 🐢 |
| 成体（分支未定） | 🐉 |
| 守护体及之后 | 🌟 💫 🌠 🔆 🌌 循环，形态越深光晕越强 |

状态会覆盖表情，并且用颜色 + 动作表达，**不用点开面板就知道它怎么了**：

| 状态 | 表现 | 提示 |
| --- | --- | --- |
| 精力 ≤ 20 | 😴 蓝紫色、上下点头、呼吸变慢 | 精力见底了，安排一次「休息」吧 |
| 饱食 ≤ 25 | 🥺 发黄、呼吸变快像在喘气 | 饱食很低，喂点东西 |

| 出任务中 | 变灰半透明、呼吸变慢 | — |

优先顺序：**困 > 饿 > 低落 > 亲密**（精力见底时它会直接睡着，不再显示别的表情）。

## 存档：导出 / 导入「迁徙胶囊」

### 存档结构

```ts
type Save = {
  v: number;              // 存档版本，从 1 开始
  savedAt: number;        // 最后保存/导出时间
  deviceId: string;       // 设备标识
  lastSettleTime: number; // 上次结算时间
  randomSeed: number;     // 确定性随机种子（额外字段，用于"刷新结果不变"）
  data: GameState;        // 全部游戏状态
};
```

### 自动保存

- 任何状态变更后 **debounce 500ms** 写入 `localStorage`（键 `stardust-migration:save:v1`）。
- `visibilitychange`（切到后台 / 锁屏）、`pagehide`、`blur` 时**立即保存**。
- `beforeunload` 也绑了，但**不是唯一手段**（移动端经常不触发它）。
- 覆盖导入前会额外留一份备份：`stardust-migration:backup:v1`。
- 如果浏览器禁用了 `localStorage`（`file://` 下的 Firefox / Safari，或隐私模式），会自动退回**内存存储**：游戏照常能玩，但会在启动时和设置页明确警告"进度不会持久化"，请用「封入胶囊」保存。

### 成长没有上限

这是刻意的设计：**只有"每天能做多少事"有上限，星兽本身可以一直变强。**

| 项目 | 上限 | 说明 |
| --- | --- | --- |
| 成长属性（体质/敏捷/智慧/感知） | **无上限** | 可以涨到几千、几万，UI 自动缩写为 `12.3k` |
| 等级 / 进化形态 | **无上限** | Lv.35 起每 13 级一个新形态，第 4、5、6…… 形态一直排下去 |
| 建筑等级 | **无上限**（30 级软收尾） | 消耗按 `cost(n) = round(cost(n-1) × 1.55) + 8` 递推；30 级约需 1.1 亿星尘 |
| 建筑效果 | **随等级线性增长** | 超出效果表后按"最后两档的正向增量"继续外推，升级永远不会变差 |
| 饱食 / 心情 / 亲密 | 100 是**舒适线**，不是上限 | 超过 100 进入**溢出区**（最多存到 200），UI 显示为 `140 +40` |
| 精力 | 0 ~ 溢出区 | — |
| 行动点 | **12 ~ 14+（每天恢复 8 点）** | ⚠️ 这条保留上限，见下方说明 |
| 离线收益 | **12 小时封顶** | ⚠️ 这条保留上限，见下方说明 |

**溢出区的意义**：把星兽喂到 140 再下线，离线时**先消耗溢出的 40**，再动核心值。
所以"出门前把它喂饱"是个真实有效的策略，而不是浪费行动点。

> ⚠️ **两条保留的上限**：行动点（每天 8 点）与离线收益（12 小时封顶）**没有去掉**。
> 它们不是"养成上限"，而是防作弊底线——去掉任意一条，"改系统时间"或"挂机"就能
> 无限刷资源，整个时间预算玩法就崩了。如果你的"无上限"是想连这两条也去掉，
> 告诉我，我把它们改成可配置项（设置页加开关）。

### 导出（封入迁徙胶囊）

设置页 → 「📦 封入胶囊（下载文件）」，会得到一个 `.json`：

```json
{
  "kind": "stardust-migration-capsule",
  "game": "星尘迁徙",
  "v": 1,
  "exportedAt": 1768000000000,
  "note": "这是一枚迁徙胶囊。把它带到新的星门，星兽就会在那里醒来。",
  "save": { "v": 1, "savedAt": 0, "deviceId": "dev_…", "lastSettleTime": 0, "randomSeed": 0, "data": {} }
}
```

也可以点「🔗 生成存档码」得到一段 **Base64 存档码**，方便直接粘贴到聊天窗口或备忘录（适合小存档）。

### 导入（在新星门唤醒）

设置页 → 「🚀 在新星门唤醒（导入）」，支持两种方式：

1. 选择胶囊文件（`.json` / `.sav`）
2. 直接粘贴 Base64 存档码或 JSON 文本

导入流程：

1. **解析 + 校验**：`try/catch` 包住 JSON 解析；结构不对直接拒绝并提示原因。
2. **安全净化**：递归剥离 `__proto__` / `constructor` / `prototype`，防原型污染。
3. **版本迁移**：`migrateSave(save)` 按版本逐级升级，再用 `fillDefaults` 补齐缺失字段（旧档、手改档都能吃）。
4. **冲突处理**：比较 `lastSettleTime`，相同则比较 `savedAt`，提示哪一份更「新」，并给出建议：

| 模式 | 行为 |
| --- | --- |
| 按建议导入 | 胶囊更新 → 替换；当前星门更新 → 合并 |
| 强制用胶囊替换 | 资源与进度都换成胶囊那一份 |
| 只合并图鉴 / 成就 | 资源、状态、任务、行动点全部保留当前这一份，只合并图鉴、成就、去过的区域、访客 |

> ⚠️ **导入前请先导出备份**。界面里也放了「先导出胶囊再决定」的按钮，避免误覆盖丢档。
> 另外，**资源与进度只能取一份**——这是为了避免用两份存档来回刷资源。

## 离线时间胶囊：它是怎么算的

### 原则

1. **没有后台运行**。关掉网页后没有任何计时器、没有 Service Worker 定时任务，存档里只留下几个时间戳。
2. **一次性结算**。再次打开时用 `now - lastSettleTime` 得到离线时长，一次算完。
3. **确定性随机**。同一份存档、同一段离线时间、同一个任务 → 结果**完全一致**，刷新页面不会变。

### 使用的字段

| 字段 | 用途 |
| --- | --- |
| `lastSettleTime` | 上次结算时刻，离线时长的起点 |
| `randomSeed` | 存档级随机种子，保证结果可复现 |
| `task.active` | 上次安排的任务类型（采集 / 探险 / 学习 / 休息） |
| `task.startedAt` | 任务起点，参与随机种子与耗时计算 |
| `task.zoneId` | 任务所在区域，决定掉落表与事件池 |

种子推导：

```js
seed = hash32(randomSeed, task.active, task.startedAt, task.zoneId, 'offline')
```

### 结算内容

- **探索收获**：区域基础掉落 + 稀有掉落 + 星尘；时长有衰减系数，避免长挂机收益爆炸。
- **状态消耗**：任务消耗（不会跌破安全下限）+ 任务结束后的空闲消耗。
- **随机事件**：按 30 分钟时间片判定，一次上线最多补 3 件，避免报告刷屏。
- **小故事**：每个区域有专属叙事碎片，拼成「你离开的第 N 小时……」的时间轴。
- **进化条件检查**：离线也会涨经验，上线后若满足条件会主动询问是否进化。

### 三条硬边界

| 边界 | 处理方式 |
| --- | --- |
| **离线收益封顶** | 12 小时以内正常结算；超出部分只按 5% 给保底星尘，并在报告里写明 |
| **时间倒退** | 若 `now < lastSettleTime`：只给保底收益，报告首条提示「星兽时差晕眩」，同时把 `lastSettleTime` 修正回当前时间 |
| **重复领取** | 结算后立即推进 `lastSettleTime` 并自动存档；同一个 `lastSettleTime` 不会结算两次 |

报告长这样：

```text
🧺 你离开的第 2 小时，【采集完成】它把脸埋进水里又抬起来，鼻尖挂着一颗不肯掉的小水珠。
   带回：🟢苔藓团×5、💎晶体碎片×3、✨星尘×4。
🍀 你离开的第 3.5 小时，【发光苔藓】它用爪子一圈圈绕开根系，只取走最外层的部分。
   带回：🍀发光苔藓×1。
```

```text
   ┌─────────┐    ┌───────────┐    ┌───────────┐

   └────┬────┘    └─────┬─────┘    └─────┬─────┘

                        ▼
```

### `state.js` —— 单一数据源

```js
store.set((state) => {
  state.pet.stats.hunger += 10; // 直接改，改完统一通知
});
```

- 所有变更走 `store.set`，因此**自动存档**与**界面重绘**只需要挂一次订阅。
- `store.subscribe` 只在 `save.js`（防抖写盘）与 `main.js`（可选）里使用，业务代码不关心落盘。

### `tasks.js` —— 在线与离线共用一套结算

`resolveTask()` 同时服务两种情况：

- **在线完成**：心跳检测到 `now >= task.endsAt`，用 `hash32(randomSeed, task.active, task.startedAt, ..., 'complete')` 做种子。
- **离线补算**：`offline.js` 用 `'offline'` 做种子，在 `min(now, task.endsAt)` 时点结算。

两者产出的结构一致（物品、状态变化、属性、经验、事件、叙事），因此报告与弹窗可以复用同一套渲染代码。

### `rng.js` —— 为什么刷新结果不变

```js
export function hash32(...parts) { /* FNV-1a 变体 */ }
export function createRng(seed) { /* mulberry32 */ }
```

游戏逻辑里**没有任何 `Math.random()`**（只在「点击星兽随机说一句话」这类纯表现层使用）。所有涉及存档结果的随机都来自 `createRng(seed)`。

### `save.js` —— 版本迁移

```js
/** MIGRATIONS[n] 负责把 v = n 的存档升级到 v = n + 1 */
export const MIGRATIONS = {
  // 1: (save) => { save.data.progress.dailyStreak = 0; return save; }, // 以后加字段就写在这里
};

migrateSave(save); // 逐级升级 -> fillDefaults() 补齐结构
```

新增字段时的标准流程：

1. `SAVE_VERSION` 从 `1` 改成 `2`。
2. 在 `MIGRATIONS[1]` 里把旧档补成新结构（或者干脆什么都不做，交给 `fillDefaults`）。
3. 老玩家打开游戏时自动迁移，不会坏档。

## 边界与防作弊处理

纯前端游戏挡不住真正想作弊的人（改 `localStorage`、改系统时间都拦不住），所以这里只保证**四点体验不被破坏**：

| 风险 | 处理 |
| --- | --- |
| 改系统时间刷离线收益 | 收益 12 小时封顶，超出部分只给 5% 保底 |
| 时间倒退 | 只给保底收益 + 「星兽时差晕眩」提示，并把 `lastSettleTime` 修正 |
| 重复领取离线收益 | 结算后立刻推进 `lastSettleTime` 并写盘；`lastSettleTime` 单调前进 |
| 挂机无限刷行动点 | 行动点按自然日恢复且**有上限**，同一天不重复恢复 |
| 导入旧档覆盖新档 | 比较 `lastSettleTime` / `savedAt`，提示哪份更新，并给出手动选择；导入前自动留备份 |
| 用两份存档来回刷资源 | 「只合并图鉴 / 成就」模式下资源与进度只取一份 |
| 坏档 / 恶意 JSON | 校验 + 迁移 + 递归剥离危险键，解析失败直接拒绝 |

## PWA 说明

- `manifest.json` 让游戏可以「添加到主屏幕」，`sw.js` 让它可以离线打开。
- `sw.js` 的作用域是 `./`（即游戏目录），**不会**劫持同域下的其他站点。
- **Service Worker 绝不参与游戏逻辑**：没有 `setInterval`、没有 `sync`、没有推送、没有后台结算。
  所有离线逻辑都由 `offline.js` 在**页面打开时**一次性完成。
- 更新缓存：改完代码后把 `sw.js` 里的 `CACHE_NAME` 版本号 +1，用户下次打开会拿到新版本。

## 常见问题

**Q：关掉网页后，星兽会自己继续探索吗？**
不会。关掉网页后逻辑完全停止，存档里只留下时间戳。再次打开时才把这段时间一次性结算成一份报告。

**Q：为什么离线收益有上限？**
为了避免「改系统时间 → 一夜暴富」破坏养成节奏。12 小时以内的收益是完整的，超出部分只给少量保底。

**Q：换了手机 / 清了浏览器缓存，进度还在吗？**
不在。存档在本地浏览器里，所以**换设备或清缓存前请先导出迁徙胶囊**。导入后星兽会在新设备醒来，并记住「换过几台设备」。

**Q：同一段离线时间，为什么我刷新两次结果一样？**
这是**故意的**。结算使用确定性随机（种子来自存档的 `randomSeed` + 任务起点 + 时间片），所以刷新不会变成「重新抽卡」。

**Q：可以直接双击 `index.html` 玩吗？**
不行。`index.html` 用的是 ES Modules，浏览器不允许通过 `file://` 加载模块（不透明来源被 CORS 拦截），必须走 HTTP。
想要双击即玩，请打开同级的 **`stardust-migration-single.html`**（单文件版，CSS 与 JS 全部内联）。

**Q：单文件版和模块版有什么区别？**
游戏逻辑完全相同，区别只有三点：单文件版把 CSS/JS 内联成一个 HTML（双击可玩）；它不含 PWA（manifest / Service Worker）；在禁用 `localStorage` 的 `file://` 环境下进度不持久。
`stardust-migration/` 里的模块版是唯一事实来源，单文件版由 `tools/build-single.mjs` 生成。

**Q：为什么有时候刷新后进度没了？**
看设置页有没有「⚠️ 当前环境无法写入浏览器本地存储」的提示。Firefox / Safari 在 `file://` 下会禁用 `localStorage`，
这时进度只存在内存里。改用本地 HTTP 服务打开，或者随手用「封入胶囊」导出，就不会丢。

**Q：数据存在哪里？会传到服务器吗？**
只存在你自己浏览器的 `localStorage` 里（键名 `stardust-migration:save:v1`）。本游戏没有任何联网上报，导出文件也只在你本地生成。
