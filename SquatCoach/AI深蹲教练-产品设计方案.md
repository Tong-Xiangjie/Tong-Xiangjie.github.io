## 1. 用户需求分析

### 1.1 要解决的问题

| # | 痛点 | 现状 | 产品能解决的问题 |
|---|------|------|------------------|
| P1 | **不知道自己做了多少个** | 锻炼时靠脑子数数，容易记错或忘记 | 自动、准确地统计深蹲次数，零误差 |
| P2 | **不知道姿势对不对** | 没有教练指导，靠镜子或感觉判断，容易养成错误动作 | AI实时分析关键点，评判姿势标准度 |
| P3 | **不知道怎么改** | 知道姿势有问题但不知道具体怎么改 | 针对每个错误维度给出具体纠正建议 |
| P4 | **不知道自己有没有进步** | 没有历史数据，锻炼效果无法追踪 | 本地保存每次训练记录，支持查看趋势 |
| P5 | **不想装APP、不想注册账号** | 市面上健身APP大多需要下载、注册、订阅 | 纯网页应用，打开即用，无需任何门槛 |

### 1.2 目标用户

**大众健身爱好者，覆盖各个层级：**
- 🔹 **新手小白**：刚开始接触深蹲，需要指导和反馈
- 🔹 **居家锻炼者**：没有私教，希望有个"AI陪练"
- 🔹 **有经验的训练者**：需要客观数据来校准动作、追踪训练量
- 🔹 **康复/矫正需求人群**：需要确保动作安全不受伤

### 1.3 使用场景

| 场景 | 描述 |
|------|------|
| 居家锻炼 | 用户在客厅/阳台录制深蹲视频，上传分析 |
| 健身房辅助 | 用户用手机录制一组动作，电脑端查看详细分析报告 |
| 训练复盘 | 训练结束后上传当天的训练视频，回顾动作质量 |
| 长期追踪 | 每周训练后导出历史记录，对比进步趋势 |

## 2. 产品功能

### 2.1 功能全景图

```
AI深蹲教练
├── 视频上传
│   ├── 拖拽上传（核心）
│   └── 点击选择上传
├── AI分析引擎
│   ├── 深蹲计数（核心）
│   ├── 姿势评判（辅助，不干扰计数）
│   ├── 姿势评分（0-100分）
│   └── 纠正建议（文本 + 可视化标注）
├── 结果展示
│   ├── 计数结果（数字 + 时间轴标记）
│   ├── 姿势细节（每个维度的状态）
│   └── 视频回放（叠加骨架线和关键点）
└── 历史记录
    ├── 记录列表
    ├── 详情查看
    ├── 数据导出（JSON）
    └── 数据导入（JSON）
```

### 2.2 核心功能详解

#### F1 - 视频上传
- **拖拽上传**：将视频文件拖到上传区域即可，支持拖入窗口任意位置触发
- **格式支持**：MP4（H.264/H.265/HEVC）、WebM、MOV
- **大小限制**：建议 ≤ 50MB（约1-2分钟视频）
- **上传反馈**：显示进度条，分析完成后自动跳转结果页

#### F2 - 深蹲计数
- **计数逻辑**：检测 "站立 → 下蹲 → 站立" 的完整周期为1次
- **计数依据**：基于髋部/膝盖的垂直位移 + 髋关节角度变化
- **精度**：排除半蹲、假动作，只统计完整动作
- **防干扰**：计数逻辑独立运行，不受姿势评判结果影响
- **时间轴标记**：在视频进度条上用竖线标记每次完整深蹲的起止帧

#### F3 - 姿势评判（5个维度）

| 维度 | 评判标准 | 检测方法 | 状态标记 |
|------|----------|----------|----------|
| **下蹲深度** | 大腿应与地面平行或更低（髋关节 ≤ 膝关节高度） | 髋部y坐标 vs 膝盖y坐标 | ✅达标 / ⚠️偏浅 |
| **膝盖方向** | 下蹲时膝盖应朝向脚尖，不外扣不内撇 | 膝盖-髋部连线与脚踝-髋部连线的夹角 | ✅正常 / ⚠️偏移 |
| **膝盖过脚尖** | 从侧面看，膝盖不应超过脚尖过多 | 膝盖x坐标 vs 脚踝x坐标（侧面视角） | ✅正常 / ⚠️超脚尖 |
| **背部挺直** | 上背部应保持一条直线，不过度弓背或塌腰 | 肩膀-髋部-膝盖的夹角 | ✅挺直 / ⚠️弯曲 |
| **身体前倾** | 躯干前倾角度不应超过45° | 肩膀-髋部连线与垂直方向的夹角 | ✅正常 / ⚠️前倾过多 |

#### F4 - 姿势评分
- 综合5个维度的达标情况，给出 0-100 分
- 评分公式示例：达标维度数 × 20 - 扣分项
- 评分等级：优秀(90+) / 良好(75-89) / 合格(60-74) / 需改进(<60)

#### F5 - 纠正建议
- 针对未达标维度，给出具体可操作的建议文案
- 示例：
  - ⚠️ 下蹲偏浅 → 建议：下蹲时想象要坐到身后的椅子上，确保大腿与地面平行
  - ⚠️ 膝盖超脚尖 → 建议：注意膝盖与脚尖方向一致，重心后移到脚跟

#### F6 - 骨架可视化
- 在视频画面上叠加 MediaPipe 输出的人体骨架线
- 用颜色标注关键关节点（髋、膝、踝、肩）
- 动画展示关节角度的实时变化

#### F7 - 历史记录
- **自动保存**：每次分析完成后自动存入浏览器本地存储
- **记录内容**：时间、计数、评分、各维度详情、视频缩略图（可选）
- **列表视图**：按时间倒序展示，支持按时间/评分筛选
- **导出/导入**：
  - 导出：一键下载 JSON 文件，包含所有历史数据
  - 导入：上传 JSON 文件，合并到本地记录

### 4.1 整体架构


**架构特点：**
- ✅ **纯静态网页**：无需后端，可部署到任何静态托管服务
- ✅ **隐私友好**：视频文件只在浏览器本地处理，不上传云端
- ✅ **无安装门槛**：浏览器打开即用
- ✅ **离线可用**：首次加载后，MediaPipe模型缓存在浏览器，后续可离线运行

### 4.2 前端技术栈

| 层级 | 技术 | 选择理由 |
|------|------|----------|
| **UI框架** | Vue 3 + Vite | 轻量、组合式API学习成本低、国内生态好；Vite构建快 |

| **图标** | Lucide Vue | 现代简洁的图标库，Vue组件化调用 |
| **状态管理** | Pinia | Vue3官方推荐，轻量够用 |
| **路由** | Vue Router 4 | 标准SPA路由 |
| **数据持久化** | Dexie.js (IndexedDB封装) | IndexedDB支持大量数据，Dexie让API更好用 |
| **视频处理** | HTML5 Video API + Canvas | 浏览器原生能力，逐帧抽取 |
| **骨架绘制** | Canvas 2D API | 在视频画面上叠加关键点和连线 |
| **构建部署** | Vite build + 静态托管 | 打包后纯静态文件，任选GitHub Pages/Vercel/Cloudflare Pages |

### 4.3 AI分析方案（核心）

#### 技术选型：MediaPipe Pose（浏览器端）

| 对比项 | MediaPipe Pose | MoveNet (TF.js) | PoseNet |
|--------|----------------|-----------------|---------|
| 精度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| 速度(CPU) | 快 | 中 | 中 |
| 速度(GPU) | 很快 | 很快 | 中 |
| 浏览器支持 | Chrome/Edge/Firefox/Safari | Chrome/Edge/Firefox | Chrome/Edge |
| 模型大小 | ~10MB | ~4MB | ~13MB |
| 维护状态 | Google持续维护 | Google持续维护 | 已停止更新 |
| 关键点数量 | 33 | 17 | 17 |
| **推荐指数** | ✅✅✅✅✅ | ✅✅✅✅ | ✅✅ |

**结论：采用 MediaPipe Pose**。33个关键点能提供更丰富的身体部位数据（包括脚踝、手指、躯干细分点等），对深蹲分析更有利。

#### MediaPipe 关键点映射（深蹲分析用）

```
MediaPipe Pose 33个关键点（归一化坐标 0-1）:

  关键点编号  |  部位       |  深蹲分析用途
  ------------|------------|------------------
  11, 12      |  左右肩膀   |  计算背部挺直度、身体前倾角度
  23, 24      |  左右髋部   |  **核心！** 判定上下蹲状态、计算髋角度
  25, 26      |  左右膝盖   |  **核心！** 判定膝盖高度、膝盖方向
  27, 28      |  左右脚踝   |  判定膝盖是否超脚尖
  29, 30      |  左右脚跟   |  辅助判定膝盖方向
```

#### 深蹲计数算法

```
输入：每帧的髋部 y 坐标数组 hipY[] 和膝盖 y 坐标数组 kneeY[]

Step 1: 平滑滤波
  smoothedHipY[i] = 移动平均(hipY[i-5 : i+5], window=11)
  → 去除抖动，让曲线更平滑

Step 2: 检测"站立→下蹲"和"下蹲→站立"的转换点
  当 smoothedHipY 从"局部最小值"变为"局部最大值" → 站立点
  当 smoothedHipY 从"局部最大值"变为"局部最小值" → 下蹲点
  （需要设置最小幅度阈值，过滤假动作）

Step 3: 配对转换点
  完整深蹲 = 站立点 A → 下蹲点 B → 站立点 C
  条件：
  - B 必须低于 A 和 C（髋部y坐标更大=在画面中更低）
  - A→B→C 时间间隔 ≥ 0.3秒（过滤快速抖动）
  - B点髋部 < 膝盖高度 × 1.05（确保蹲得足够深，半蹲不计入）

Step 4: 计数 = 完整深蹲周期数

输出：
  - totalCount = N
  - timestamps[] = [t0, t1, t2, ...]  每次深蹲的起止时间戳
  - frameMarkers[] = 对应的帧号（用于视频时间轴标记）
```

#### 姿势评判算法（5个维度）

```
以下以单帧（下蹲最深帧）的评判为例：

维度1 - 下蹲深度
  条件：hipY(髋部) ≥ kneeY(膝盖)  → 达标 ✅
  条件：hipY < kneeY × 1.05        → 偏浅 ⚠️
  （注：y坐标越大表示画面中位置越低）

维度2 - 膝盖方向（正面视角）
  kneeHipVec = kneePos - hipPos
  ankleHipVec = anklePos - hipPos
  angle = 两向量夹角
  条件：angle 在正常范围(60°~120°) → 达标 ✅
  条件：angle < 60°  → 膝盖内扣 ⚠️
  条件：angle > 120° → 膝盖外撇 ⚠️

维度3 - 膝盖过脚尖（侧面视角）
  条件：kneeX - ankleX < threshold → 达标 ✅
  条件：kneeX - ankleX ≥ threshold → 过脚尖 ⚠️

维度4 - 背部挺直度
  shoulderHipVec = shoulderPos - hipPos
  hipKneeVec = hipPos - kneePos
  angle = 两向量夹角
  条件：angle 在 160°~180° → 挺直 ✅
  条件：angle < 150°  → 弓背/塌腰 ⚠️

维度5 - 身体前倾
  shoulderHipVec的垂直分量 = shoulder.y - hip.y
  shoulderHipVec的水平分量 = shoulder.x - hip.x
  tiltAngle = arctan(水平分量 / 垂直分量)
  条件：tiltAngle < 45° → 正常 ✅
  条件：tiltAngle ≥ 45° → 前倾过多 ⚠️
```

### 4.4 数据存储方案

#### 存储选型对比

| 方案 | 容量 | 结构化查询 | 适合场景 |
|------|------|-----------|----------|
| localStorage | ~5MB | ❌ 只能key-value | 简单配置 |
| sessionStorage | ~5MB | ❌ 只在当前会话 | 临时数据 |
| **IndexedDB** | **几百MB+** | **✅ 支持索引查询** | **结构化历史记录** |

**选择 IndexedDB**，通过 Dexie.js 封装后 API 简洁。

### 4.5 视频处理流程

```
用户拖拽视频文件
       │
       ▼
┌─────────────────┐
│ File API 读取    │  ← 拿到 File 对象
└────────┬────────┘
         │
         ▼
┌────────────────────────────┐
│ Video 元素 + Canvas 逐帧提取 │
│                              │
│  video.currentTime += 1/fps  │  ← 每 1/30 秒抽一帧
│  canvas.drawImage(video)     │
│  canvas.toDataURL()          │  ← 拿到每一帧的画面
└────────┬───────────────────┘
         │ 逐帧送入
         ▼
┌────────────────────────────┐
│ MediaPipe Pose 推理          │
│                              │
│  const pose = new Pose(...)  │
│  pose.setOptions({          │
│    modelComplexity: 1,      │  ← 0:轻量/1:平衡/2:精度
│    smoothLandmarks: true,    │
│    minDetectionConfidence:   │
│    0.5, minTrackingConf: 0.5 │
│  })                         │
│  pose.estimateLandmarks(    │
│    canvas, async=true        │
│  )                           │
└────────┬───────────────────┘
         │ 每帧输出 landmarks[33]
         ▼
┌────────────────────────────┐
│ 后处理：计数 + 姿势评判       │
│                              │
│ hipY[] = landmarks[23]...   │  ← 提取关键点坐标数组
│ 平滑滤波 → 找转换点 → 配对   │
│ 计算各维度的关节角度和距离    │
└────────┬───────────────────┘
         │
         ▼
┌────────────────────────────┐
│ 渲染结果 + 保存历史          │
└────────────────────────────┘
```
