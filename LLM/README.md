# 从零手写的小型语言模型（字符级 Transformer）

一个**不依赖任何深度学习框架**的中文小语言模型。前向传播、反向传播、LayerNorm、因果自注意力、
AdamW、采样器全部手写在 `tiny-transformer.js` 里，配套一份自撰语料和一个可以在浏览器里直接训练的单文件页面。

```
LLM/
├── index.html              ← 主页面：打开就能训练 / 生成 / 存档（单文件，无外部依赖）
├── tiny-transformer.js     ← 模型本体（前向 + 手写反向传播 + 采样 + 评估）
├── checkpoint.js           ← 存档：权重与优化器状态打包成自包含字符串
├── vocab-char.js           ← 字符级词表 + 训练/验证切分
├── corpus.js               ← 语料汇总入口
├── corpus-extra.js         ← 扩充语料（文言、白话、音节表）
├── corpus-more.js          ← 自撰现代白话段落
├── _demo-template.html     ← index.html 的模板（模型与语料由构建脚本注入）
├── _build-v2.mjs           ← 生成 index.html（校验内联脚本语法后再落盘）
├── _autograd-oracle.mjs    ← 独立 autodiff，用来验证手写反向传播
├── _test-grad.mjs          ← 总测试：梯度、过拟合、采样器、对比 bigram
├── _test-checkpoint.mjs    ← 存档往返测试
├── _trial.mjs              ← 超参搜索
├── _corpus-stats.mjs       ← 语料统计
└── _test-v2html.mjs        ← 在 Node 里用 DOM 桩跑通 index.html
```

> 最早那版单隐层 MLP 的页面已被这一版替换（它当时未被 git 跟踪，文件本身没有留存）。
> 那一版的问题清单、以及每一项的实测后果，完整保留在下面第一节里。

## 一、最早那版为什么"蠢"

最早那版（已无文件留存，见上面的说明）是实打实量过的，不是感觉：

| 毛病 | 原来的做法 | 后果 |
|---|---|---|
| 上下文里没有顺序 | `CTX=8` 个字的向量**首尾拼成一个长向量**喂给 MLP | 对"我打你"和"你打我"算出几乎一样的隐藏层，等于一个丢掉语序的词袋；位置信息为零 |
| 语料被复制一遍 | `TEXT = CORPUS + CORPUS` | 同一个句子出现两次，loss 天然偏低，而且没有留验证集 |
| 字表太稀疏 | 912 字 / 203 个不同字，其中 130 个只出现 1–2 次 | 大多数字的嵌入向量几乎没被训练过，等于随机噪声 |
| 没有衡量标准 | 只打印训练损失 | "看起来在下降"不等于学会了，也发现不了过拟合 |
| 采样参数自相矛盾 | 重复惩罚 1.5 + 窗口 12 + `top-k=10` | 惩罚过强、候选过少，生成要么死循环要么莫名其妙 |
| prompt 靠复制最后一个字补齐 | `while (ctx.length < CTX) ctx.push(ctx[ctx.length-1])` | 开头的上下文是"你你你你你你"这种假序列 |
| 优化器太朴素 | 固定学习率梯度下降，无裁剪、无衰减 | 小语料上要么学不动，要么一步跨过头 |

**但是**：真正让它"学不会"的并不是上面这些，而是下面这件事。

## 二、致命的部分：反向传播是错的

这一版写完之后我用独立手段去查反向传播，陆续抓出 **6 个 bug**。它们的共同点是
**都不报错、loss 也照常下降**，所以靠肉眼看曲线永远发现不了：

1. **残差支路的梯度没回传。** `h1 = h0 + ao·Wo` 里 `h0` 那一项漏了，
   每层输入收到的梯度少一大块；`Wo = 0` 时甚至整块变成 0。
2. **激活缓存被逐层覆盖。** 只有一份 `h1/h2/h3/f1/f2`，反传到第 0 层时读到的是**最后一层**的激活，
   越靠前的层错得越离谱。
3. **注意力反向只取了本头切片。** 前向里每个头只影响自己那 `d_head` 维，反向却把 `D` 维全加了进来，
   `dq/dk/dv` 被重复累加 `H` 倍。这个错误特别隐蔽：唯一不用这段代码的 `Wo` 梯度始终是对的。
4. **softmax 反向的临时量被多个 (head, 位置) 共用**，`dot` 项被互相污染，`dq` 直接算成 0。
5. **logits 缓冲用错步长。** 按 `ctx` 分配却按词表大小索引，只有序列长度恰好等于 `ctx` 时才对；
   否则概率全为 0，注意力一路的梯度直接归零。
6. **`1/T` 只乘在了两处。** `forward` 返回平均交叉熵，`backward` 却只给 `dlogits` 和 LayerNorm 乘了 `1/T`，
   中间从 `dh2` 拷出来的队列全漏了，词嵌入梯度正好大了 `T` 倍。

修好之后，验证困惑度从 **385 降到 285**，训练困惑度从 **390 降到 102**（同样的超参、同样的步数）。

还有一个**独立的** bug，是加存档功能时才暴露出来的：

7. **`zeroGrads()` 漏清 `g.Wout`。** 权重共享时 `Wout` 就是 `E`，因此它不在 `paramList()` 里、
   也就不会出现在 `bindings` 中；但 `backward` 仍然往 `g.Wout` 里累加。
   结果**其他所有参数每步都规规矩矩清零，唯独输出层投影的梯度跨步一直累积**。
   这个 bug 会让训练极不稳定，而且因为"读档后接着训"和"一口气训完"结果不一致才被发现。

## 三、怎么确认反向传播是对的

**没有用有限差分当主判据。** 参数是 float32（相对精度约 6e-8），
若参数只有 0.02 量级而 ε 取 1e-3，ε 会被量化掉 1–2 个 ULP，
商值误差能到 100% —— 假失败率高到没法用。

真正的判据是 `_autograd-oracle.mjs`：里面有一个**磁带式反向模式自动微分**（`class N` + 拓扑排序回传），
它把**同一个前向计算重新搭一遍**，再和手写的 `backward` 逐参数块对拍。
这是真正独立的第三方实现，能精确指出是哪一层的哪个参数块错了。

```
$ node LLM/_autograd-oracle.mjs
T=5 D=8 L=2 H=2 tie=false      参数量=  2089 loss=3.360739/3.360739 不合格块=0/38 ✅
T=5 D=8 L=2 H=2 tie=true       参数量=  1953 loss=2.810148/2.810148 不合格块=0/37 ✅
T=3 D=4 L=1 H=1 tie=false      参数量=   417 loss=3.486552/3.486552 不合格块=0/22 ✅
T=8 D=16 L=3 H=4 tie=false     参数量= 10561 loss=3.472252/3.472252 不合格块=0/54 ✅
T=6 D=12 L=2 H=3 tie=false     参数量=  4289 loss=2.905079/2.905079 不合格块=0/38 ✅

全部配置与 autodiff 一致 ✅
```

判据用**绝对差相对于该参数块最大梯度**的混合形式。纯相对判据会把"解析值本来就是 0"的元素
（例如序列很短时 `bk` 的梯度恒为 0）判成错，而那只是 float32 舍入噪声。

`_test-grad.mjs` 里另外还有几道防线：

- 沿负梯度走一步，loss 必须下降；
- 把 `backward` 会写到的**每一块**梯度缓冲都填成 1，调用 `zeroGrads()` 后必须全为 0（这条专门防第 7 个 bug）；
- `resetBatchGrads()` 之后重跑，梯度必须**逐位复现**（证明没有跨步残留）；
- 小模型要把一条 5 步序列的 loss 压到 0.05 以下（能背下来 = 整条反向链路可用）。

**教训**：这些错误都不会让程序报错，loss 也经常照常下降 —— 因为 Adam 会按参数自适应归一化，
方向对但幅度错的梯度依然能训练。只有拿一个独立实现逐块对拍，才能确定每一层都对。

## 四、模型结构

标准 pre-LN 解码器，唯一区别是反向传播手写：

```
h0 = E[token] + P[pos]
for each layer:
  z   = LayerNorm(h0)
  q,k,v = z·Wq, z·Wk, z·Wv
  at  = softmax(causal(q·kᵀ / √d_head))
  ao  = at · v
  h1  = h0 + ao·Wo                 # 残差
  z2  = LayerNorm(h1)
  f   = ReLU(z2·W1 + b1)·W2 + b2
  h2  = h1 + f                     # 残差
h5   = LayerNorm(h2)
logits = h5·Wout + bout
loss = 平均交叉熵
```

- **位置编码**是学习出来的（不是正弦函数）
- **注意力严格因果**：位置 t 只能看到 ≤ t
- **权重共享**：`Wout` 直接复用 `E`（GPT-2 的做法）。V=1233/D=32 时省掉约 39k 参数，
  而且每个字只有一个向量要学，小语料上收敛明显更好
- 每层的激活缓存和 LayerNorm 统计量都**按层各存一份**

## 五、存档

`checkpoint.js` 把权重和 Adam 状态打包成自包含字符串：float32 原始字节 → gzip → base64。
不含代码，只有数字，但带了形状和词表指纹。

实测（V=1233 / 参数量 67,185）：

| | 大小 |
|---|---|
| 纯 JSON | 5,697 KB |
| 本存档（含 Adam，base64 后） | 976 KB |
| 仅权重 | 315 KB |

能塞进 localStorage，所以页面会自动记住上次的训练结果，下次打开直接接着训。

**读档时会硬性校验**，因为"安静地读进一个尺寸不对的模型"比报错危险得多：

- 形状不符（`vocab/dModel/nLayers/nHeads/ctx/tieWeights`）→ 抛错
- 词表指纹不符（语料换过了，id 就对不上了）→ 抛错
- 内容被截断或损坏 → 抛错，不会返回一堆垃圾

`_test-checkpoint.mjs` 覆盖了往返逐位一致、**续训等价性**（存 → 读 → 接着训，
结果必须和一口气训完**逐位相同**，最大差 0）、以及上面每一条错误路径。

> 顺带一提：只比"数值相等"是不够的。曾经的一个 bug 就是读档后 `Wout` 不再是 `E` 的别名，
> 两块参数数值相同但各自独立更新，**权重共享静默失效**。
> 所以测试里专门查对象同一性（`E === Wout`），而不是只比值。

## 六、数据与实测指标

语料 **13,780 字**，2,307 个不同字，平均每字出现 5.97 次。
`minFreq=2` 过滤后词表 **V=1,218**（低频字折进 `unk`），
按**字符预算**切成训练 11,475 / 验证 2,179 token。

> 切分按字符预算而不是段落个数：段落长短差别很大，按个数切会让验证集只有两百多字，指标噪声大到没法看。

| | 验证困惑度 | 下一字准确率 |
|---|---|---|
| 随机猜测 | 1,218 | — |
| bigram 基线 | 275.8 | 16.5% |
| 模型（D=32 L=2 H=4，900 步） | 284.9（最好 302.5） | 17.0% |
| 单文件 demo（D=32 L=2 H=4 lr=0.008，约 1000 步） | **246.8** | **18.8%** |

修复前同样配置的验证困惑度是 **385**，训练困惑度 **390**（几乎没学会）。
修复后训练困惑度降到 **102–105**，说明它现在是真的在拟合，而不只是在抖动。

## 七、诚实的局限

- **语料规模是真正的瓶颈**，不是网络结构。1.4 万字下字符级 bigram 已经是很强的基线
  （它在这个规模上几乎见过所有二连字），Transformer 需要多得多的数据才能体现长距离建模的优势。
- 它学会了常用搭配和短句结构（"为什么"、"学习"、"时候"、"已经"），**学不会语义**。
  生成结果里有重复和语病是正常的。
- 参数几万，单线程纯 JS，比 PyTorch 慢得多。这里图的是**每一行都看得懂**，
  不是性能。实测 D=64/L=2/ctx=32 时前向 14.9 ms、前向+反向 45.0 ms。
- 验证集只有 2,179 token，困惑度本身就有波动；曲线上的抖动是真实的抽样噪声，不是绘图问题。
- 没用 dropout（`dropout` 参数留着但恒为 0），没用学习率调度，没有批矩阵乘法。
